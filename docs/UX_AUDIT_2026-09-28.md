# MyTerra UX/UI audit — 2026-09-28

**Scope:** full walkthrough as the target user (millennial, zero growing experience), on the
production build at phone (390×844, 360×740), tablet and desktop (1440×900) sizes, light and dark.
**Personas:** (A) London backyard 8 × 5 m, total beginner, 15 min/day, 2 people, owns nothing;
(B) Amsterdam balcony 4 × 1.5 m, part-covered, 3–5 h sun, 5 min/day; (C) skips setup;
(D) established farm with hens and bees (test fixture). Trial states: day 1, last day, expired.
Auth flows (sign-up, wrong password, reset request, reset link) run against mocked Supabase
responses so no production account was created.

Status: **Fixed** = shipped in the UX pass commit (see `LAUNCH_PLAN.md`, "UX pass").

## Still open

- **"Food in ~N months" ignores the season.** `describeSuggestion()` in `src/lib/suggest.js` uses `crop.days` only and never checks the crop's `harvest` window. In September it tells a beginner Strawberry "Plant now · food in ~4 months" (autumn-planted strawberries fruit next June, ~9 months) and Broad Bean "food in ~5 months" (autumn sowings crop in May–June, ~8 months). Seen in onboarding "Your matched plants" and Plan "For you". The Plan calendar's beginner tip has the same flaw: "Try Strawberry — plant a row today and you'll be harvesting in weeks" (`Manuals.jsx`, `beginnerTip`). On the website it shows in the matched-plants shot (`p-ob-plants.webp`) and the tour video's set-up segment. Fix: when planting now + `days` lands outside the harvest window, count to the start of the next window ("first fruit next June"); only offer tip examples that really give food within weeks. Then re-shoot those two website visuals.
- **Pro plan promises features that don't exist:** "Multi-zone management" and "Advanced analytics". `multizone` and `analytics` are listed as Pro features in `entitlements.js` but nothing checks them, so Basic already gets several zones and nobody gets analytics. Only the assistant is Pro-only. Owner decision: build them or reword the Pro list (ties to Stage 7's open Basic zone-cap decision).
- **Contact link** on the website is a personal Gmail address.
- **Subscription on account deletion:** a live Basic/Pro subscription is cancelled automatically only if a `PADDLE_API_KEY` secret (permission `subscription.write`) exists in Supabase → Edge Functions → Secrets. Without it the app refuses to delete a paying account and asks the person to email support. Which case applies is not visible from here.
- **Account deletion not run end-to-end on production.** Verified: the function is deployed (verify_jwt on), answers CORS preflight for the app's origins, rejects unauthenticated calls; every code path passed locally against a mock. Worth one test with a throwaway account.
- Farm Designer copy for a balcony user who skipped setup still says "Design your farm" on a 100 × 60 m canvas.

## Not verifiable from here (check in the Supabase dashboard)

- **Emails reach real users:** Auth → SMTP. Supabase's built-in sender only delivers to team members
  and is heavily rate-limited; confirmation and reset emails need a custom SMTP provider.
- **Redirect allow-list** includes `https://myterra.farm/app` and `https://myterra-sigma.vercel.app/app`
  (Auth → URL Configuration). If not, links fall back to the Site URL; the landing page now forwards
  them to `/app`, so both work, but the allow-list is cleaner.
- Real-device frame rate of the 3D preview on low-end phones.
